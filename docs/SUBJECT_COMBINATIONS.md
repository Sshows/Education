## 3. Поддерживаемые комбинации профильных предметов

### Canonical pair key

Ключ комбинации **всегда** строится сортировкой двух ID по алфавиту:

```
"biology" + "chemistry" → "biology+chemistry"
"chemistry" + "biology" → "biology+chemistry"  // тот же ключ
```

Порядок выбора НЕ важен. Сравнение всегда нечувствительно к порядку.

## 5. Сопоставление программ с парами предметов

Каждая группа образовательных программ (ОП) требует конкретную пару предметов.

Пример:
- `B057` (Информационные технологии) → **Математика + Информатика**
- `B086` (Общая медицина) → **Биология + Химия**
- `B049` (Право) → **Всемирная история + Основы права**

Данные хранятся в `DEMO_PROGRAM_GROUPS` и в БД как `subject_pair_key`.

---

## 6. Почему соответствие нечувствительно к порядку

```
Mathematically: sort([A, B]).join("+") === sort([B, A]).join("+")
```

Это гарантирует одинаковый результат вне зависимости от того, как пользователь выбрал предметы.

**Frontend**: `subjectPairKey(a, b)` в `ent-subjects.ts`  
**Backend**: `_pair_key(a, b)` в `ent_subjects.py`  
Обе функции реализуют `sorted([a, b]).join("+")`.

## 7. Уровни качества данных

| Уровень | Значение | Отображение |
|---------|---------|------------|
| `official` | Официальный источник НЦТ / МНВО | ✓ зелёный badge |
| `imported` | Импортировано из официального документа | синий badge |
| `secondary` | Вторичный источник | оранжевый badge |
| `demo` | Демонстрационные данные | жёлтый badge ⚠ |
| `unknown` | Источник не определён | серый badge |

> **Аксиома**: никогда не показывать демо-данные как официальные.  
> Демо всегда сопровождается баджем и пояснением.
